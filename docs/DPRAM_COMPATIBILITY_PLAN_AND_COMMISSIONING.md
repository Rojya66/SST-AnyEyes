本文是待实施方案，不代表下面列出的兼容功能已经加入程序。本次只编写方案，没有修改控制、通信源码或编译配置。

建议双方约定：保留旧Block1/2/3和插件地址；补齐旧接口可实现的功能；现代PI、保护、预充及详细故障使用现有邮箱21扩展。485继续只使用AnyEyes或VOFA。Word应同步修订为这个明确版本。

### 1 控制功能边界

| 功能 | 建议约定 |
|---|---|
| HVAC启停 | 保持原bit0和地址；启动请求CHB+DAB，停止撤销两路请求 |
| CHB/DAB独立请求 | 保持COM_PLUSE_ON/OFF bit1/bit0；实际PWM动作仍受当前模式和状态机约束 |
| 故障复位 | 完全停机、PWM关闭且存储不忙时受理；受理与故障源消失分开反馈 |
| 开环/闭环 | 使用扩展点2的ac_mode=0/1；不得把文档“恒压/Vf”直接等同当前“直流电压闭环” |
| 独立合分闸 | 若确需该功能，新增维护开关命令与状态机联锁，统一处理停机/PWM/开关许可和超时；不能接回旧直接DO函数。未实现前界面禁用并返回不支持 |
| 恒功率、下垂、谐波等 | 当前无对应完整控制路径；本轮兼容明确为不支持。需要这些功能时另立控制需求及测试 |
| PT/CT配置 | 不能仅存下配置字；若要支持，必须定义实际标定参数、接线含义、生效时机和持久化，否则不支持 |
| HVDC/LVDC/LVAC启停 | 本DSP只承接当前HVAC/CHB端口；其他端口应由ARM路由到对应设备，不能让本DSP假应答成功 |

普通停机当前是封波/切换停机流程。若要求Word中的渐降功率后停机，须单独增加停机斜坡和超时退出机制；紧急停机和故障封波仍独立。

### 2 旧遥调与现代参数的处理原则

- PORT_V_SET可以明确映射到现代单模块DC目标，不需要改变旧地址。
- STATCOM_Q_SET是无功功率，iq_reference_a是电流，不能按固定倍率直接互换。第一版建议界面使用扩展Iq点7。若必须保留旧无功给定，要另外定义单相/三相Q到Iq的换算或外环、低电压处理及符号，并做闭环验证。
- 文档12个旧PI字段不应猜测成当前4个Kp/Ki。上位机PI编辑控件直接使用现代点24、25、33、34；旧PI字在点表标为不支持写入。若必须沿用旧PI地址，需要另定布局版本、逐字段比例和范围，不能静默复用旧缩放因子语义。
- 写整个43字时，上位机采用读改写，未支持字段保持原回读值；DSP应根据明确的可写字段及变化检查拒绝不支持修改。不能把旧影子值复制进来就宣布已应用。
- 邮箱20仅保留“旧块回读完成”意义，不等于参数已保存。新增旧事务结果应有计数/时间和结果码；现有扩展21的ack_sequence仍只用于扩展请求，不能冒用来确认没有序号的旧请求。
- 保存只用显式SAVE。若约定上电自动恢复，启用CHB_LOAD_EEPROM_PARAMETERS=1并验证存储镜像和参数校验；若保持0，应明确通过LOAD恢复。两种约定必须选定并写入版本记录。

### 3 对外故障映射建议

为兼容Word的故障位含义，在Block3打包阶段生成独立对外字，不改变内部故障位或保护链：

| 对外位 | 建议来源 |
|---|---|
| bit10过流 | 硬件端口过流、原软件过流或CHB_FAULT_AC_OVERCURRENT |
| bit11欠压 | 经确认的模块/端口欠压来源 |
| bit12过压 | 硬件端口过压、原软件过压或CHB_FAULT_DC_OVERVOLTAGE |
| bit13通信 | 真正的通信故障来源，不再直接复制内部复用bit13 |
| bit14SYNC | 真正的同步故障来源；PLL故障是否并入须在点表明确，详细码保留 |
| bit15故障汇总 | 有效故障来源或现代状态FAULT；不再仅照搬内部0x75FF汇总结果 |

预充超时、非法配置、开关反馈故障等若无完全对应的旧位，不硬塞成无关原因；bit15置位，详细原因读取扩展控制故障和故障码表。原内部故障字仍可通过历史记录供追溯。

这会改变Block3线上语义，必须发布新的“兼容布局版本”。不能让新旧上位机在没有版本识别时各按一套含义解码。现有扩展请求format version=1、点号和地址可以保留；兼容布局版本与维护请求格式版本是不同概念。

## 三 双方冻结点表的交付格式

一行对应一个可读字、写入点或位，至少包含：

```text
点名 / 区域 / DSP字节地址 / DPRAM逻辑字偏移 / ARM CPU地址
数据类型 / 字数 / 字节与字顺序 / 倍率 / 单位 / 读写权限
bit掩码或枚举 / 允许范围 / 生效条件 / 是否保存
刷新周期 / 数据有效条件 / 执行结果位置 / 协议布局版本
```

倍率统一约定为 `raw = round(工程值 × scale)`，解码为 `工程值 = raw / scale`。有符号字先转int16再解码；位图按uint16。超限应拒绝写入并返回结果，不能擅自夹紧后报告完整成功。

## 四 与上位机逐步对点

### 步骤1 冻结版本和通信路径

记录本次DSP out及源码版本、宏配置、ARM固件版本、上位机版本和点表版本。确认PC→LAN→ARM→DPRAM实际路径，不把N510透明485与ARM并口服务混为一条已实现链路。

只读联调可以用SST_ENABLE_DPRAM=1、SST_SIMULATOR_MODE=1，预期遥测可读、写参数和启停被拒绝。需要可写联调时使用SIMULATOR_MODE=0。SST_BENCH_INPUT_SIM保持0，它与DPRAM不能同时使能。

先做无功率通信联调，再做开关和功率动作验收；接触器输出/反馈的两项宏独立约定，不能随DPRAM开关自动打开。

### 步骤2 对地址和16位数据通路

双方共同检查：

```text
DSP地址 = 0x66000000 + 2 × 逻辑字地址
ARM地址 = DPRAM_ARM_BASE + 2 × 逻辑字地址
```

例如维护请求首字的逻辑偏移是0x1600，ARM字节偏移是0x2C00。若ARM使用uint16_t数组，则访问ram[0x1600]，不能写成ram[0x2C00]。

在双方明确划定的临时测试字上核对0x1234、0xA55A、0x8001等模式，排除地址乘2错误、字节互换和符号误读；不得借用控制、参数、输出区或邮箱做随机写测试。没有临时测试区时先做下述只读事务。

### 步骤3 做只读识别和第一笔事务

检查现有回复头magic=0x5353、维护version=1、point_count=54；读取remote_allowed判断控制源。检查现代遥测版本戳可形成完整快照，32位10ms节拍持续推进。

发送op0读点6，不改变参数。确认回复ack_sequence匹配、ack_result=0，actual_value与0x66002D4C的点6实际值一致。一次成功读点即可验证“请求写入→邮箱中断→后台解析→回复读取”全链。

### 步骤6 对错误和互锁

- 模拟器模式：读成功，写/启停返回模式禁止。
- 写采样周期只读点9：拒绝且采样周期不变。
- 访问点54：地址错误；CRC错误：格式错误，目标值不变。
- 参数越界、运行中禁止写：明确拒绝，原值不变。
- 存储忙时START受限，STOP/OFF仍有效；不要在真实发波时用断点拖住ISR验证。
- 同序号同载荷：只返回缓存结果；同序号不同载荷：错误。结果为BUSY后条件恢复，应使用新序号。
- 旧块中不支持的模式、开关和PI修改：不能出现“回显了就算成功”。

当前扩展结果码：0成功、1地址、2只读、3范围、4忙/非停机、5模式禁止、6存储、7格式/CRC/序号冲突。以上具体失败条件以相应事务入口为准。

### 步骤7 对启停、状态流和故障

先在无功率条件验证命令入口、优先级和反馈显示，再按台架条件验证实际动作。正常闭环状态顺序为0→1→2→3→4；任意阶段故障应进入5。ACK只表示受理，必须等待state、PWM及经核实的物理反馈才能显示动作完成。

逐项核对：CHB请求、DAB请求、STOP、同帧STOP/START、同位OFF/ON、运行中复位拒绝、停机复位，以及故障后不自动重启。若用原START bit0，它会同时请求CHB和DAB；只验证CHB时用明确的独立请求，不把总启动当CHB专用命令。

在可控的软件/硬件测试环境分别触发快速过流、快速过压、预充超时和PLL故障，核对对外位图、扩展控制故障、五位码及历史。不要通过取消保护或在PWM开放时暂停ISR来制造测试条件。

### 步骤8 对保存、加载和断电恢复

停机发SAVE，先确认请求受理，再等storage_pending=0且storage_result=0，随后读参数实际值。按选定策略做断电恢复或显式LOAD，核对持久化参数恢复、运行使能没有恢复为启动。邮箱20、保存ACK和最终保存结果分别记录。

### 步骤9 通信负载和10kHz时序验收

并发持续遥测、参数读取、插件读取和一次保存，测现有GPIO的ISR脉宽及周期；核对最坏执行时间小于100us并有余量、没有丢TAD。后台发布和EEPROM不得造成关中断长阻塞。

ARM可先按100～200ms刷新界面；DSP扩展快照约30ms构建，但实际发布受后台负载影响。故障/命令结果使用独立轮询，超时判定须根据实测最坏响应设置；页面刷新慢不应阻塞命令事务。测试通过后再提高采集频率。

### 步骤10 冻结联调证据

交付最终CSV/Word、字段支持清单、请求/回复原始记录、逐点结果、固件与点表校验、宏配置及ISR测时截图。每个点至少有“读、允许写、非法写、实际生效、是否保存”的适用项结果；没有通过的点保留为不支持或未验收。
