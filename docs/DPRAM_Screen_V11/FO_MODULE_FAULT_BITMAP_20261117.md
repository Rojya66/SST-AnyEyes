# 701模块故障位置位图与保护使能修正

日期：2026-11-17。DSP工程：`D:\Code\SST\AnyEyesVersion_DpramCompat`。

现场已将UNIT的`TEST_BYPASS_EXTERNAL_INTERLOCKS`恢复为0，本次按故障光纤正常上报处理。此次只修改DSP，不改ARM、UNIT或主控FPGA工程，不改变PI、保护限值和控制配置。

## 1. U2与三块701是四路

当前`Analog_PluginUnit_3`宏实际值为2，采样板使用U2；`IO_PluginUnit_2`宏实际值为3，开关量板使用U3。这两个历史名称不能按末尾数字直接理解，见`SstBoardConfig.h`。

|Port_FB_EN位|当前对应插件|用途|
|---|---|---|
|bit0 / 0001|U2采样板|采样插件AD硬件保护反馈|
|bit6 / 0040|U8，A相701输入板|A相模块故障汇总|
|bit10 / 0400|U12，B相701输入板|B相模块故障汇总|
|bit14 / 4000|U16，C相701输入板|C相模块故障汇总|

`0x4441=0x0001+0x0040+0x0400+0x4000`，因此是四路；`0x4440`才只有三相701的三路。正常保留U2的bit0=1，否则采样板经FB回传的端口硬件保护会被主控屏蔽。软件阈值保护仍是独立路径，不能用它代替这一路使能。

## 2. 同步遗漏如何修正

遥调实际更新的是`Port_AD_PORT_EN`、`Port_FB_EN`及`Port_FO_1/2/3_EN`，写FPGA也使用这些变量；原`FaultCheckAndDispose_StepOne()`却用初始化时复制到`PORT_Regulate_DATA`的旧使能筛选故障。

现在该故障函数统一直接使用`Port_*_EN`。硬件写入和软件故障解析取同一组对象，不再增加一层副本同步，不修改已有FPGA寄存器地址和写函数。

```text
原43字遥调 / 57项扩展APPLY
  -> Port_AD_PORT_EN、Port_FB_EN、Port_FO_1/2/3_EN
       -> 原FPGA写函数：更新硬件使能
       -> FaultCheckAndDispose_StepOne：使用同一变量筛选锁存
```

## 3. 屏幕新增只读点

这三个点是**遥测上报**，不需要写遥调邮箱。复用Word原33字遥测末尾三个保留字，其余地址、块长度和原`PORT_FAULT`位定义保持不变。

|用途|原字段/块字号|Modbus十六进制|十进制偏移|40001编号|ARM字节地址|DSP字节地址|
|---|---|---|---|---|---|---|
|A相701故障位置|Reserved_1[0] / word30|051E|1310|41311|60000A3C|66000A3C|
|B相701故障位置|Reserved_1[1] / word31|051F|1311|41312|60000A3E|66000A3E|
|C相701故障位置|Reserved_1[2] / word32|0520|1312|41313|60000A40|66000A40|

类型为`uint16`位图，比例1，权限R。屏幕使用Modbus 03/04读，无需ARM修改或额外协议。ARM按字节序透传，不将它解释为故障枚举码。虽然旧结构体字段为`short`，原始33字视图是`ushort`，线上位模式原样保留；屏幕按无符号16位处理。

代码在`SstDpramTelemetry_BuildLegacyBlock()`末尾直接赋值：

```c
words[30] = Port_FOStatusRead(Input_A_PluginUnit_8, 1U) & Port_FO_1_EN;
words[31] = Port_FOStatusRead(Input_B_PluginUnit_12, 1U) & Port_FO_2_EN;
words[32] = Port_FOStatusRead(Input_C_PluginUnit_16, 1U) & Port_FO_3_EN;
```

源码中每组外面有一个明确的使能判断：整组FO使能为0时不访问该板，输出0。没有安装或不使用的701，其FO使能应为0，不能把无效总线读值当作真实故障。

取值是701的`FO_LATCH`硬件锁存与当前FO使能的按位与；不读取旧软件`FOLatch_*_TAD`，不依赖核心是否处于运行状态。光纤故障发生后恢复光纤，位仍可能保持1，直到原硬件故障复位流程清除锁存。硬件锁存反映该板捕获的故障位置，不是实时光纤电平表，也不保证记录首次锁存之后所有新增的故障。

`FB_EN`控制是否把某板故障送入主控保护；新三个位置诊断点不再按`FB_EN`二次屏蔽。因此可能出现“位置有故障但主控没有动作”，这时应检查对应FB使能是否关闭。FO未使能的通道始终输出0。

三相701的诊断与`SST_PHASE_A_ONLY_TEST`独立，单相控制也保留这三处诊断。它们只代表各自701的物理输入，不表示B/C控制环已启用。

补充有效性位图同步更新：`19A2=C204`表示原块word18、25、30、31有效；`19A6=0001`的bit0表示word32有效。旧word0..15有效位图`19A1`不变。

## 4. bit对应哪个UNIT

**bitN对应对应相701的物理输入`OP_IN[N]`。1表示该通道已锁存故障且FO使能为1；0表示没有选通的锁存故障。**

|位|掩码|701物理输入|
|---|---|---|
|bit0|0001|OP_IN[0]|
|bit1|0002|OP_IN[1]|
|bit2|0004|OP_IN[2]|
|bit3|0008|OP_IN[3]|
|bit4|0010|OP_IN[4]|
|bit5|0020|OP_IN[5]|
|bit6|0040|OP_IN[6]|
|bit7|0080|OP_IN[7]|
|bit8|0100|OP_IN[8]|
|bit9|0200|OP_IN[9]|
|bit10|0400|OP_IN[10]|
|bit11|0800|OP_IN[11]|
|bit12|1000|OP_IN[12]|
|bit13|2000|OP_IN[13]|
|bit14|4000|OP_IN[14]|
|bit15|8000|OP_IN[15]；V1.1远程FO使能中此位保留，通常不使能|

没有把高/低8位重新压缩，也没有按`NHA_module_A/B/C`重编号。模块编号取决于现场故障光纤接线；**不能仅凭程序推断UNIT序号与输入序号连续对应。**

例如A相UNIT3的故障光纤接U8的`OP_IN[2]`，则该模块故障时`051E`的bit2=1，即至少包含`0004`。若该UNIT实际接`OP_IN[8]`，则应显示bit8，即`0100`。同时捕获输入0和2时为`0005`，屏幕应分别点亮两个报警灯，不将5当成一个故障编号。

原`0502.PORT_FAULT`继续提供总故障分类，`19C4`及详细码列表继续提供过流/过压等故障原因；新三个字只补位置，不替代原因码。位置为0也不等于没有软件过流、配置、预充等故障。

## 5. 屏幕与CCS验证

1. 核对现场故障光纤：把每个UNIT的编号、所属相、对应701输入序号记成表，再为屏幕灯绑定相应字和bit。首次验证使用只有控制系统、没有主回路的条件。
2. 读`0200..0204`确认使能，原FO掩码仍按Word低15位。A相输入2参与保护需`0201.bit2=1`，U8汇总送主控需`0204.bit6=1`；正常保留U2的`0204.bit0=1`。只改参数时仍按43字底稿及邮箱2步骤提交，成功后读`1987=0`。
3. DSP持续Run，用受控的UNIT故障测试源或已确认电平的故障光纤方式触发指定输入。屏幕读取`051E/051F/0520`；以输入2为例，期望对应相的字包含`0004`。同时读`0502`和详细码区区分位置与原因。
4. CCS观察硬件表达式`FPGA_Interface[Input_A_PluginUnit_8 - 2].FO_LATCH`及`Port_FO_1_EN`；二者按位与应与`051E`相同。B/C相同理。不要向只读`FO_LATCH`或遥测区写一个值来冒充故障产生。
5. 若需软件调试断点，在`FaultCheckAndDispose_StepOne()`读取FB之后看`FBLatch_TAD`、`Port_FB_EN`，再在FO筛选处看当前`Port_FO_1/2/3_EN`。这些断点属于故障联调，只在无主回路时使用；正常运行用不停机观察。
6. 排除故障源、完全停机后，屏幕发原故障复位命令`00FA.bit0=1`，完整写16字再写`1FFE=1`。等待原两阶段硬件复位完成，确认701硬件锁存和新位图清零；未排除的故障不能据此认定已恢复。
7. 换一个输入再触发，确认新的bit与原故障不同。测试一个FO未使能通道时，其新位图应为0；FB未使能而FO使能时，新点仍可显示位置，但不通过该板FB触发主控保护。

后台周期与原块3相同，约60ms刷新。只读点不需要邮箱1/2提交；右邮箱3通知仅为提示，屏幕也可直接轮询固定地址。

## 6. 中断边界与验证记录
