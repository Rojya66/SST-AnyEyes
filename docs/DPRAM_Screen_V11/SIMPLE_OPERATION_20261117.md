# 屏幕维护操作简化记录（2026-11-17）

## 修改目的

屏幕按键只提交操作号，DSP受理后清零，执行完成后反馈结果。取消屏幕请求序号校验、同号请求缓存及序号冲突拒绝；屏幕无需记住上次序号，保存失败后可以再次按保存重新尝试。

此处只修改0x1B00维护操作区；原Word的16字遥控、43字遥调及遥测布局不变。本文所有寄存器地址均为十六进制Modbus逻辑字地址。

## 寄存器及按钮

| 地址 | 读写 | 本版含义 |
|---|---|---|
| 1B00 | 可读写，解析忽略 | 保留，屏幕无需使用 |
| 1B01 | 写操作号、读回自清零 | 1应用候选参数，2保存活动参数，3加载EEPROM参数，4用实际值刷新候选区；0无操作 |
| 1B02 | 只读 | DSP完成计数，每笔处理结束自动加1，16位回绕；失败也计数，忙时丢弃的额外按键不计数；屏幕可不用 |
| 1B03 | 只读 | 0成功、1地址、2只读、3范围、4忙/未完全停机、5拒绝、6存储错误、7不支持 |
| 1B04 | 只读 | 1操作处理中，0空闲；最终结果发布后最后清0 |
| 1B05 | 只读 | 错误参数/字段号；FFFF表示未细分 |
| 1B06 | 只读 | 最近完成的操作号 |

屏幕“保存”配置成一次写数值按钮：按下时向1B01写2，松开不写0，由DSP清零。加载、应用、刷新按钮分别写3、1、4。按钮在1B01非0或1B04为1时禁用；不能配置成周期写入或保持值，否则每次空闲时再次写入都会重新执行。

保存步骤：

1. 停机，CHB和DAB都关闭，确认1B01=0、1B04=0。
2. 确认修改参数已实际生效。原43字遥调处理成功后可直接保存；57项候选区则先写1B01=1应用并核对实际区。
3. 只写1B01=2。
4. 等1B01=0且1B04=0，再读1B03：0才是保存成功，6是EEPROM失败。操作字清0仅表示DSP消费了请求。
5. 失败后可再次写1B01=2重试，无需操作1B00或匹配1B02。

加载只写1B01=3，完成判断相同。加载成功后活动参数已恢复，若还要编辑候选区，写1B01=4刷新候选并等待完成，再修改。

## DSP实现

`Source/04_App/10_Host/SstDpramScreen.c`：

- `SstDpramScreen_ProcessTransactions()`读取1B01，非0就按本次新请求处理，不再读取1B00。受理时先置busy和处理中结果，再清操作字，防止受理期间显示上一笔成功。
- SAVE受理后由原`SstParameterStore_Service()`分步写入和读回校验。完成前busy保持1；额外操作字清0丢弃，不排队、不重新启动保存。
- `CompleteScreenTransaction()`先写结果、错误位置、完成操作号和DSP完成计数，最后清busy。被拒绝的操作也有完成反馈，结果4且busy=0表示请求因未停机/存储占用而未执行。
- 1B01为0时只做原后台发布，不因上一笔操作号相同而再次执行。

补充点表版本1982改为0102。旧上位机若有1B00序号生成及1B02序号匹配逻辑，需要移除；地址不变，1B02已改成独立的完成计数。

## 边界与现场问题

所有处理仍在后台，未给10kHz FPGA中断增加调用；EEPROM驱动、镜像格式、保存范围、停机判据和控制参数没有改变。当前CHB_LOAD_EEPROM_PARAMETERS为1，本次保留。

本次解决“每次保存要更换请求序号”的操作问题。现场1B03=6、storagePosition=0仍表示第一笔EEPROM写入无应答，不会因取消序号而自动恢复；再次按保存会实际重新访问器件。
