# SST_CHB_V1.0 屏幕通讯 V2.1

DSP 工程在 CCS 中显示为 `SST_CHB_V1.0`，Debug 和 Release 均生成 `SST_CHB_V1.0.out`。本地检出目录沿用原路径。这里的 V2.1 是屏幕通讯版本。

屏幕通过 ARM 的 Modbus TCP 502 访问 DPRAM，默认 Unit ID 1。现有 ARM 固件透传 FC03/04/06/10，原有串口调试协议独立于本接口。组态使用 [V2 点表](DPRAM_MODBUS_POINTS.csv)。旧 V1.1 地址、旧插件镜像通知 4–19、维护邮箱 21 和屏幕操作字 1B01 均已退役。旧屏须改用 V2 点位，实际组态与固件配套切换。

| 区域 | 零基字地址 | 用途 |
| --- | --- | --- |
| 控制 | 0100–0103 | 操作号和 A/B/C 三个观察掩码 |
| 遥调 | 01FF–023E | 操作号和 63 个参数 |
| 遥测 | 0500–05B3 | 签名、回执、运行/预充/开关状态、交流与均压、501/701/202/403、UNIT 风扇配置 |
| 模块 | 0600–06A7 | 三相各 14 台，每台 Udc、Ir、Ig、PT100 |
| 当前故障 | 0700–0709，0720–073F | 核心原因、当前报码及原始来源 |
| 历史 | 0800–0803，0810–0A4F | 最近 32 条，每条 18 字；条目 0 最新 |
| 物理邮箱 | 1FFE、1FFF | ARM 写左邮箱，DSP 写右邮箱 |

表内字地址以十六进制表示。ARM 字节地址为 0x60000000 + 2w，DSP 字节地址为 0x66000000 + 2w，40001 号制为 40001 + w，w 取零基字地址的十进制值。U16/I16 占一字，I16 是二补码。U32 / IEEE 754 F32 低字在低地址，每个 16 位字在网络上高字节先发。架构共有 8192 字，普通数据止于 0A4F，余址保留。

## 邮箱事务

上电等待期间签名无效。连接先检查 `0500=5353`、`0501=0201`，确认 `050C/050D` 的 10 ms 节拍在递增。V2.0 屏幕须升级为 V2.1 后再允许写入。FC06/FC10 的 Modbus 回显只说明 ARM 完成访问。

- 控制先读 0504、写 0100–0103，最后以 FC06 写 1FFE=1。等 0504 变化、0505 与操作号相符，再取 0506。结果为 0 表示受理，动作看 0512/0513、0514/0515 和实际触点。
- 遥调先读 0507。01FF 操作号 1 为应用，2 为保存，3 为加载，4 为读取实际值。应用一次写 01FF–023E 全 64 字，再以 FC06 写 1FFE=2。其他操作只写 01FF 后通知。等 0507 变化、0508 匹配且 050B=0，再读回 0200–023E 和 0509/050A。失败也回实际值，050A 给出错误字地址或 FFFF。
- DSP 完成综合遥测通知右邮箱 3，遥调完成通知 20（十进制，0x0014）。同一轮 20 优先。硬件邮箱无队列，读可应答通知，屏幕以完成计数而非右邮箱是否抢读到来确认。一次只留一笔待处理，超时时先查看状态和回执，再由操作员决定下一步。

| 操作值（十进制） | 控制请求 |
| --- | --- |
| 1 / 2 | 启动 / 停止 CHB |
| 3 / 4 | 启动 / 停止 DAB |
| 5 / 6 | 整机停机 / 故障复位 |
| 7 / 8 | 手动合 / 分 QF1 |
| 9 / 10 | 手动吸合 / 释放 KT1 |
| 11 / 12 | 允许 / 禁止手动合闸 |
| 13 | 提交 0101–0103 观察掩码 |

与命令动作无关的观察字填零。023B 选择 CHB 开环（0）或闭环（1），023C 选择手动（0）或自动（1）。两项均在完全停机时通过遥调应用。手动合闸需合闸许可；先合 QF1 并确认 DI7 合位、DI8 非分位，再单独合 KT1。闭环自动启停按现有预充与反馈顺控。开环两桥可独立启停。闭环 DAB 进入 RUNNING 后按原斜坡投入。闭环故障复位还要确认 QF1 真实分位、KT1 释放且反馈稳定。

## 参数与故障观察

- `0202/0203` 设预充连续时间和总超时，默认 20/1000 个 10 ms 拍；`0239/023A` 设开关反馈确认和动作超时，默认 3/100 拍。开关反馈计时独立于预充。预充条件看 0524，已连续达标看 051A，状态耗时看 0518。
- 参数在完全停机下整组校验并应用。EEPROM v5 增加风扇阈值，加载 v1–v4 镜像时阈值取 170/235，v4 中已有的开关时间仍照常加载。默认上电只恢复有效 v5 镜像中的风扇阈值。`CHB_LOAD_EEPROM_PARAMETERS=1` 上电加载整组参数，构建配置见 05A6。台架输入仿真跳过上电恢复。0230 软件保护开关仅当前运行期有效，启停、手动许可和观察选择只存在 RAM。
- 0236–0238 为 A/B/C 运行 PM。物理组 1 对应 UNIT1–8，组 2 对应 UNIT9–14。观察掩码可在运行中修改，筛选条件为观察选择、实际运行 PM、在线和 Udc 可用。同时显示 0598–059A 已应用掩码及 059B–059D 有效槽。无效槽显示空白，Ir/Ig 是最近滤波样本，PT100 约每 0.41 s 更新。观察数据只走显示。
- 0589–058B 是 501 当前缺失，058C–058E 是 core=8 时保存的跳闸位置。0592–0594 是 701 实时输入，0595–0597 是 701 各板首锁存。05A0 为 403 首报板卡，05A8 为 202 首锁存。0701/0702 区分核心原因和五位报告码。读取遥测不会清 F2 或保护锁存。
- 综合、模块、历史分别用 0502、0503、0800 核对发布前后戳相同且为偶数。历史序号和 10 ms 时刻来自 DSP 后台，复位保留，重新上电重置。跨掉电追溯由屏幕归档。501 预充超时或失联的历史记录保存当时的判断证据，后续分 QF1 造成的掉线只出现在当前位图。

## UNIT 风扇均压阈值

- 在停机状态读回活动参数，整组提交停扇 `023D` 和开扇 `023E`。默认 170/235 count，要求 `0 ≤ OFF < ON ≤ 1983`。count 是 UNIT 本地 `SCI_UDC` 的比较值，约 1 V/count，实际电压以采样标定为准。比较为严格小于和大于，因此 OFF=0 时采样无法触发停扇，ON=1983 时采样无法触发开扇。成功应用后读取 `0200–023E`，另按 SAVE 保存入 EEPROM。
- `05AA/05AB` 为本次分发事务请求的 OFF/ON，`05AC` 为配置代号。`05AD–05AF` 和 `05B0–05B2` 分别为 A/B/C 相已确认及拒绝位图，bit0–13 对应 UNIT1–14。按当前投入 PM 查找两个位图均为 0 的模块，这些模块尚无本次配置回报。`05B3` 为配置状态，0 未开始，1 等待确认，2 已确认，3 配置失败，4 使用原固件默认阈值或台架未启用分发。停机应用或加载后发起事务，尚未得电的 UNIT 可以在闭环预充时重新下发并确认。
- 闭环预充的 `0524.bit6` 表示风扇配置就绪。自定义阈值要求配套 501/UNIT 位流，投入的 UNIT 都须确认本次事务。配置失败报码 `39105`（核心原因 9）。停机时可分别核对 `023D/023E` 的活动值、EEPROM 保存回执和 `05AD–05B3` 的 UNIT 配置结果。风扇转速和输出触点须从实物读取。
- CCS 调试在停机时填写 `g_chb_dab_params.fan_off_count`、`fan_on_count`，然后置 `g_chb_dab_command.fan_config_apply=1`。控制任务消费请求后清零，`g_chb_dab_status.fan_config_*` 对应屏幕事务状态。
- 每次闭环预充在 QF1 合闸命令前开始新事务。全部投入 UNIT 在线后开始 200 ms 配置等待，预充总超时仍独立计时。兼容旧 501 时只接受原默认配对。已支持配置的 501 仍须收到该板投入 UNIT 的确认。
- 501 `XA=2A/2B` 暂存停扇与开扇值，`2C` 提交，`2D` 为能力标识 `4641`，`2E/2F` 返回同一事务的确认和拒绝位图。501 复用 `C000` 备用发送时隙承载 `C1–C6` 配置帧，UNIT 通过原 `SIN_R` 诊断时隙返回应用结果。负 `SCI_UDC` 在本地风扇比较时按零处理，光纤保留原采样。

## Windows 联调

仓库内的 [Windows 联调界面](../../tools/hmi_v2/README.md) 使用同一份点表。启动命令如下。

```powershell
python tools/hmi_v2/panel.py --probe <ARM_IP>
python tools/hmi_v2/panel.py <ARM_IP>
```

第一条只读签名和遥测。第二条打开运行、模块、遥调及故障画面，操作员点击后才发送命令。现场触摸屏工程尚未定位，实际屏幕须按此点表和事务顺序重新绑定。ARM 继续透传 Modbus；自定义阈值使用支持配置回报的 501 和 UNIT 位流。

## 本次变更

V2.0 基线为 `fd727eb`。DSP 后台统一经 `SstDpramHost_Service` 消费两个左邮箱块，控制沿用原启停和维护开关入口。V2.1 在遥调块末尾新增两项风扇均压阈值，并发布下发与确认状态。V2 发布器分片写三类只读快照，原插件镜像及双重屏幕维护入口已退出生产调度。链接器把普通数据映射为单一区段 `.DPRAM_V2`，类型为 NOINIT，最后两字保留为硬件邮箱。


## 验证

- V2.0 基线曾用 CCS 12.5 在独立工作区导入，Debug 和 Release 均生成 SST_CHB_V1.0.out。TI C6000 8.3.12 的默认 A 相、三相与 EEPROM 上电加载、关闭 DPRAM 三组构建通过，链接图验证 NOINIT 和两个邮箱边界。
- V2.1 用 TI C6000 8.3.12 编译链接了默认 A 相、三相加 EEPROM 全量恢复、关闭 DPRAM 的仿真器模式及台架输入仿真四个构建。主机测试验证了邮箱回执、遥测、参数迁移及 Windows 客户端 Modbus TCP 回环。`python tests/dpram_screen_layout.py` 核对 908 点、999 字及物理邮箱。
- 501 与 UNIT 的光纤配置、回执和风扇逻辑由 Icarus Verilog 联合仿真验证。PLL 和乘法器使用行为模型。Pango 布局布线及柜内动作待验证。
- 701 首锁存可以单独看到，即使即时硬件封波让 DSP 未收集到具体子分类。现有开环首次发波与故障分类的时序边界仍适用，应同时看 PWM 状态和 701 锁存。现场 ARM/触摸屏、刷屏时延和实际电气动作待台架验证。
