# SST_CHB_V1.0 屏幕通讯 V2.0

DSP 工程在 CCS 中显示为 `SST_CHB_V1.0`，Debug 和 Release 均生成 `SST_CHB_V1.0.out`。本地检出目录沿用原路径。这里的 V2.0 是屏幕通讯版本。

屏幕通过 ARM 的 Modbus TCP 502 访问 DPRAM，默认 Unit ID 1。现有 ARM 固件透传 FC03/04/06/10，原有串口调试协议独立于本接口。组态使用 [V2 点表](DPRAM_MODBUS_POINTS.csv)。旧 V1.1 地址、旧插件镜像通知 4–19、维护邮箱 21 和屏幕操作字 1B01 均已退役。旧屏须改用 V2 点位，实际组态与固件配套切换。

| 区域 | 零基字地址 | 用途 |
| --- | --- | --- |
| 控制 | 0100–0103 | 操作号和 A/B/C 三个观察掩码 |
| 遥调 | 01FF–023C | 操作号和 61 个参数 |
| 遥测 | 0500–05A9 | 签名、回执、运行/预充/开关状态、交流与均压、501/701/202/403 |
| 模块 | 0600–06A7 | 三相各 14 台，每台 Udc、Ir、Ig、PT100 |
| 当前故障 | 0700–0709，0720–073F | 核心原因、当前报码及原始来源 |
| 历史 | 0800–0803，0810–0A4F | 最近 32 条，每条 18 字；条目 0 最新 |
| 物理邮箱 | 1FFE、1FFF | ARM 写左邮箱，DSP 写右邮箱 |

表内字地址以十六进制表示。ARM 字节地址为 0x60000000 + 2w，DSP 字节地址为 0x66000000 + 2w，40001 号制为 40001 + w，w 取零基字地址的十进制值。U16/I16 占一字，I16 是二补码。U32 / IEEE 754 F32 低字在低地址，每个 16 位字在网络上高字节先发。架构共有 8192 字，普通数据止于 0A4F，余址保留。

## 邮箱事务

上电等待期间签名无效。连接先检查 `0500=5353`、`0501=0200`，确认 `050C/050D` 的 10 ms 节拍在递增。FC06/FC10 的 Modbus 回显只说明 ARM 完成访问。

- 控制先读 0504、写 0100–0103，最后以 FC06 写 1FFE=1。等 0504 变化、0505 与操作号相符，再取 0506。结果为 0 表示受理，动作看 0512/0513、0514/0515 和实际触点。
- 遥调先读 0507。01FF 操作号 1 为应用，2 为保存，3 为加载，4 为读取实际值。应用一次写 01FF–023C 全 62 字，再以 FC06 写 1FFE=2。其他操作只写 01FF 后通知。等 0507 变化、0508 匹配且 050B=0，再读回 0200–023C 和 0509/050A。失败也回实际值，050A 给出错误字地址或 FFFF。
- DSP 完成综合遥测通知右邮箱 3，遥调完成通知 20（十进制，0x0014）。同一轮 20 优先。硬件邮箱无队列，读可应答通知，屏幕以完成计数而非右邮箱是否抢读到来确认。一次只留一笔待处理，超时时先查看状态和回执，再由操作员决定下一步。

| 操作值（十进制） | 控制请求 |
| --- | --- |
| 1 / 2 | 启动 / 停止 CHB |
| 3 / 4 | 启动 / 停止 DAB |
| 5 / 6 | 整机停机 / 故障复位 |
| 7 / 8 | 手动合 / 分 QF1 |
| 9 / 10 | 手动吸合 / 释放 KT1 |
| 11 / 12 | 允许 / 禁止手动合闸 |
| 13 | 提交 0101–0103 观察掩码 |

与命令动作无关的观察字填零。023B 选择 CHB 开环（0）或闭环（1），023C 选择手动（0）或自动（1）。两项均在完全停机时通过遥调应用。手动合闸需合闸许可；先合 QF1 并确认 DI7 合位、DI8 非分位，再单独合 KT1。闭环自动启停按现有预充与反馈顺控。开环两桥可独立启停。闭环 DAB 进入 RUNNING 后按原斜坡投入。闭环故障复位还要确认 QF1 真实分位、KT1 释放且反馈稳定。

## 参数与故障观察

- `0202/0203` 设预充连续时间和总超时，默认 20/1000 个 10 ms 拍；`0239/023A` 设开关反馈确认和动作超时，默认 3/100 拍。开关反馈计时独立于预充。预充条件看 0524，已连续达标看 051A，状态耗时看 0518。
- 参数在完全停机下整组校验并应用。EEPROM v4 增加两项开关时间，读取旧 v1–v3 镜像时补默认值。0230 软件保护开关仅当前运行期有效。启停、手动许可和观察选择只存在 RAM。当前构建默认关闭自动从 EEPROM 加载，实际构建配置看 05A6。
- 0236–0238 为 A/B/C 运行 PM。物理组 1 对应 UNIT1–8，组 2 对应 UNIT9–14。观察掩码可在运行中修改，筛选条件为观察选择、实际运行 PM、在线和 Udc 可用。同时显示 0598–059A 已应用掩码及 059B–059D 有效槽。无效槽显示空白，Ir/Ig 是最近滤波样本，PT100 约每 0.41 s 更新。观察数据只走显示。
- 0589–058B 是 501 当前缺失，058C–058E 是 core=8 时保存的跳闸位置。0592–0594 是 701 实时输入，0595–0597 是 701 各板首锁存。05A0 为 403 首报板卡，05A8 为 202 首锁存。0701/0702 区分核心原因和五位报告码。读取遥测不会清 F2 或保护锁存。
- 综合、模块、历史分别用 0502、0503、0800 核对发布前后戳相同且为偶数。历史序号和 10 ms 时刻来自 DSP 后台，复位保留，重新上电重置。跨掉电追溯由屏幕归档。501 预充超时或失联的历史记录保存当时的判断证据，后续分 QF1 造成的掉线只出现在当前位图。

## Windows 联调

仓库内的 [Windows 联调界面](../../tools/hmi_v2/README.md) 使用同一份点表。启动命令如下。

```powershell
python tools/hmi_v2/panel.py --probe <ARM_IP>
python tools/hmi_v2/panel.py <ARM_IP>
```

第一条只读签名和遥测。第二条打开运行、模块、遥调及故障画面，操作员点击后才发送命令。现场触摸屏工程尚未定位，实际屏幕须按此点表和事务顺序重新绑定。ARM 源码和 Pango 位流沿用现有配套版本。

## 本次变更

基线为 `fd727eb`。DSP 后台统一经 `SstDpramHost_Service` 消费两个左邮箱块；控制复用原启停/维护开关入口。遥调表连接已有控制参数、保护和 PM 应用函数；只新增两项运行可配置的开关时间。V2 发布器分片写三类只读快照，原插件镜像及双重屏幕维护入口已退出生产调度。链接器把普通数据映射为单一区段 `.DPRAM_V2`，类型为 NOINIT，最后两字保留为硬件邮箱。


## 验证

- CCS 12.5 在独立工作区导入，Debug 和 Release 均生成 SST_CHB_V1.0.out。若本地检出目录直接位于 CCS 工作区下，使用匹配工程名的目录，或从独立工作区导入当前检出。
- TI C6000 8.3.12 通过默认 A 相、三相加 EEPROM 上电加载、关闭 DPRAM 三个构建。实际链接图核对 NOINIT、两个邮箱的边界和零装载数据。
- 生产源码测试覆盖邮箱确认、停机权限、参数回读和 EEPROM 迁移、开关延时、501 F1/F2、701 锁存、42 槽遥测和历史。点表审核覆盖 896 点、987 字。Windows 客户端用本机 Modbus TCP 回环以及界面绑定测试验证。
- 701 首锁存可以单独看到，即使即时硬件封波让 DSP 未收集到具体子分类。现有开环首次发波与故障分类的时序边界仍适用，应同时看 PWM 状态和 701 锁存。现场 ARM/触摸屏、刷屏时延和实际电气动作待台架验证。
