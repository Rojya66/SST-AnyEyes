## 5. 原块1：让屏幕遥控直接作用于当前核心

控制块仍为逻辑地址`0x00F0～0x00FF`、16字、左邮箱1。

| 文档字段 | 地址（逻辑字 / DSP字节） | 修改目标 |
|---|---|---|
| HVAC START/STOP bit0 | `00F2/00F3`；`660001E4/E6` | 进入现有启动/停止请求，外部状态随实际状态机变化 |
| CHB ON/OFF bit1 | `00F8/00F9`；`660001F0/F2` | 单独提交/撤销CHB请求，受当前开闭环模式和故障联锁约束 |
| DAB ON/OFF bit0 | 同上 | 单独提交/撤销DAB请求，按当前可用运行条件执行 |
| RESET bit0 | `00FA`；`660001F4` | 完全停机后清可复位故障；活动故障再次出现时重新上报 |
| SWITCH_ON/OFF | `00F6/00F7`；`660001EC/EE` | 补齐受控开关命令入口，按实际进线、旁路与外部开关接线建立映射 |
| SWITCH_EN | `00FB`；`660001F6` | 维护外部合闸许可，影响实际受理条件和状态回读 |
| SYS_MODE/PORT_MODE | 块2首字 / `00F4` | 保留Word的运行/测试、自动/手动和主模式语义，不能直接把“恒压/Vf”当成开环、把PQ当成闭环 |

STOP和封波优先；故障不能被ON覆盖；重复START不重复复位软启动；重复合闸不反复重触发线圈脉冲。文档要求“一笔一个动作”，因此不依赖同帧STOP+RESET等组合行为。

开关输出/反馈宏及现场电平继续单独配置。无真实反馈时不能把“命令已发出”填成“触点已闭合”。本DSP只驱动已实现的CHB/DAB端口，其他端口位不应误路由到本机。

## 6. 原块2：参数写入、实际值和持久化一致

遥调块仍为逻辑地址`0x01FF～0x0229`、43字、左邮箱2，回写通知20。

| 旧字段 | 地址（DSP字节） | 计划接入 |
|---|---|---|
| PORT_V_SET | `0x6600040E` | `g_chb_dab_command.dc_voltage_ref_v`，明确其为单模块直流目标；旧输入比例在最终点表冻结 |
| PORT_F_SET | `0x66000410` | 按当前操作模式接开环输出频率或PLL额定频率，不能把并网输入频率当成可强制改变的电网频率 |
| PORT_V_P_1 / PORT_V_I_1 | `0x66000434/436` | 作为组1电压Kp/Ki的候选直接入口；必须先确定Word未写明的缩放 |
| PORT_I_P_1 / PORT_I_I_1 | `0x66000438/43A` | 作为组1共用dq电流Kp/Ki的候选直接入口，保留正确有符号编码 |
| P/Q、STATCOM相关给定 | `0x6600040A/40C/422`等 | 按物理量确认后适配；Q与Iq必须根据电压、dq定义和单/三相功率关系换算，不能直接改单位赋值 |
| AD/FO/FB保护使能 | `0x66000400～408` | 逐一接入真实支持的保护使能路径，回读实际配置；不能只改缓存 |
| 组2/组3 PI及其他字段 | 原址 | 查清实际控制对象，不能把“组2/3”擅自解释为B/C相，也不能恢复旧注释代码后默认已接入 |

需要特别处理的历史问题：旧DPRAM.C被注释的PI处理把这些字段用作PLL_Factor、Volt_Factor等缩放因子，并不是直接Kp/Ki。新实现必须按冻结后的屏幕含义重新适配，不能简单取消注释。

写入流程：完整块 → 后台候选副本 → 权限/状态/范围/组合校验 → 一次提交。失败时活动参数不发生部分变化。只修改一个字时，其他未改参数保持其原浮点精度，避免整块整数回写导致PI量化漂移。

DSP对块2返回的是**实际生效参数编码**，不能把未经校验的输入缓存原样回显。与其他参数入口共用同一份活动参数，避免“屏幕设一份、控制器用另一份”。普通PI/保护参数初版按停机可写；允许在线调整的目标值如确需支持，单独定义限幅与斜坡。

应用与保存分开：默认写参数只改RAM，显式SAVE才写EEPROM；设置完成、正在保存、保存成功/失败分别报告。Word未分配并口SAVE动作地址，需在补充普通寄存器中定义。自动上电加载策略与现场参数基线一并冻结，不能因新工程启用DPRAM就自动加载未知旧EEPROM值。

## 7. 原块3：状态、故障和工程量按Word输出

遥测块仍为逻辑地址`0x0500～0x0520`、33字，右邮箱通知3。

- `PORT_RUN_STATUS`：建立内部状态到外部状态表，输出完整Word语义及低6位状态，不把内部0～5或当前兼容枚举直接丢给屏幕。
- `PORT_STATUS`：本次按V1.1使用**bit13～14的S_Mode**，bit15保留。只在DPRAM打包层移动这些位，内部共享位域和FPGA数据格式继续按各自定义处理。
- PWM闭锁位保持Word的`1=闭锁`；接触器/断路器位对应真实定义，消除目前GNDSwitch/ISOSwitch错填外部断路器反馈的问题。
- `DC_V`补齐生产者，明确它与单模块均压、串联总母线的关系。Word只有“直流母线电压”，最终点表必须固定含义，不能在不同运行模式下悄悄变单位。
- P/Q、V/I、频率、功率因数统一符号、比例和饱和处理；当前单相AN与三相线电压的字段语义分别说明，禁止用不存在的B/C测量冒充正常三相。
- 插件镜像只对实际配置且有数据生产者的插件发布有效数据；补充有效性/刷新计数，避免旧缓存被当成新采样。

对外`PORT_FAULT`由专用打包函数生成，保留内部原保护位不变：

| 故障来源 | 对外Word位 |
|---|---|
| 快速软件过流、原RMS过流、可确认的硬件端口过流 | bit10 |
| 快速软件过压、原软件过压、可确认的硬件端口过压 | bit12 |
| 通信故障 | bit13，不能继续塞原软件过压 |
| 同步故障 | bit14，不能继续塞原软件过流 |
| 欠压、频率及其他文档类别 | 各自对应位，汇总时覆盖全部原因位 |
| 任一真实控制/保护故障 | bit15；即使某原因无法用旧分类准确细分，也必须显示总故障 |

预充超时、PLL未锁定、非法配置等保留准确的内部原因和五位详细码，不能为了凑旧16位分类而伪报通信或其他硬件故障。具体分类映射和详细码一起列入交付点表。

## 8. 文档缺失项：补普通Modbus点表，不能声称已有屏幕自动可见

V1.1的旧43字遥调块没有完整的预充门槛、快速OC/OV、原保护计时等地址；旧33字遥测只有故障位图，没有五位详细码表。第6节的PARAMETER/Save是A5 5A串口对象协议，没有给出它们对应的DPRAM寄存器地址。部分PI/电压比例还写着“按版本确认”。因此“仅按Word、屏幕完全不增加点位、就能操作所有现有控制参数”不能只靠DSP修改自动成立。

建议在原地址保持的基础上增加**普通Modbus寄存器**：屏幕按地址读写数值，最后写应用/SAVE/LOAD操作字；DSP后台检查并给出结果。不要求屏幕实现邮箱21的CRC、请求帧或对象协议。

候选区域如下，均位于当前DSP保留尾区；实施时核实ARM/屏幕无其他用途后冻结逐字表：

| 用途 | DPRAM逻辑字范围 | DSP字节范围 | 主机权限 |
|---|---|---|---|
| 版本、状态、维护结果、有效性 | `0x1980～19BF` | `0x66003300～337F` | R |
| 详细故障码、原始故障字 | `0x19C0～19FF` | `0x66003380～33FF` | R |
| 参数待应用区 | `0x1A00～1A7F` | `0x66003400～34FF` | R/W |
| 参数实际生效值 | `0x1A80～1AFF` | `0x66003500～35FF` | R |
| APPLY/SAVE/LOAD及事务控制 | `0x1B00～1B0F` | `0x66003600～361F` | 按字段分R/W |

补充参数覆盖当前已实现的运行给定、PI、PLL、限幅、DAB、预充及新旧保护阈值。每项固定类型、符号、单位和比例，可复用现有参数表的编码规则，但屏幕不需要提交“点号+数据”请求，而是直接写该参数自己的寄存器。

启动/停止仍走原块1，不把待应用参数区当成持续启动命令区。参数应用在最后操作字到达时触发，不能每拍扫描变化就立即应用半组参数。两字浮点若确需使用，须明确每字网络字节序、两字顺序及提交边界；默认原块继续使用Word规定的16位整数。

原文档已分配的屏幕按钮/显示项通过DSP适配使用原址。补充项若屏幕已有厂商自定义地址，应优先接既有地址；若尚无，则屏幕需要绑定这些新增普通寄存器。仅修改DSP不能给屏幕自动增加编辑框或故障详情页。

## 9. 不能混作“通信兼容”的控制功能

Word还列出恒功率、下垂、谐波注入/治理、其他电气端口、传感器变比/接线配置，以及正常停机降功率过程。这些部分当前CHB/DAB核心并不全部具备。

实施先做逐项能力矩阵：已经存在的行为直接接入；需要新增受控开关/参数入口的列为本次兼容实现；需要新控制算法或硬件能力的单列设计及验证工作。不能把不支持的模式写进缓存后回报成功，也不能把任意Word模式映射成同一个闭环来声称全功能兼容。

如果“完全兼容”要求这些控制算法也全部可用，则它们必须进入新增控制功能阶段并分别验证，不能把仅完成DPRAM收发当成最终完成。本规划的核心交付是当前实际具备的CHB/DAB功能通过原屏幕点表真实可控、可读、可追溯，全部未闭合事项会明确列出。

## 10. 10kHz时序与验证

GPIO101中断继续仅清通知并置标志。所有协议转换、参数校验、寄存器打包、存储和故障列表工作放后台；每轮通信工作有界，不在ISR新增大块DPRAM复制、等待或格式化输出。

右邮箱不是队列，要防止当前“写块3后立即被插件通知覆盖”造成屏幕漏收。根据ARM/屏幕按Word读取方式安排发布节拍；无ACK时不能仅凭DSP延时宣称绝不漏事件。实际遥测允许直接定期读固定区，通知与快照一致性在联调时验证。

验证分五步：

1. **基线与布局**：记录基线构建结果；检查16/43/33字布局、固定地址与所有位掩码；新旧工程可同时导入。
2. **通信与参数软件测试**：使用实际16位寄存器样例，覆盖负PI、缩放、只改一项、整组拒绝、运行时写入、STOP优先、重复命令、保存失败及实际值回读。
3. **故障/状态编码**：逐类输入内部故障，检查Word旧故障位和五位码的一致性；校验bit13/14用途、总故障位、S_Mode位置、PWM位极性。
4. **构建回归**：新工程Debug/Release完成编译；验证DPRAM/仿真器、AnyEyes/VOFA，以及单相/三相相关组合不因兼容层破坏。具体必要组合及结果写入构建记录。
5. **控制板实测**：屏幕或Modbus工具→真实ARM→DPRAM→DSP→回读，先停机验证参数及故障报告，再验证受控启停。对比改造前后10kHz ISR典型/最大占用及后台通信延迟；编译和主机测试不能替代这一项。
