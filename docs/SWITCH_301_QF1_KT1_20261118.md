## 2. 开关及指示输出

| DSP DOUT位 | 新代码成员 | S301端子 | 整机用途 | 驱动方式 |
|---|---|---|---|---|
| bit0 | `Port_DOUT.Dout.Qf1ClosePulse` | X2_1、X2_2 | 经外部K1驱动QF1合闸 | 脉冲 |
| bit1 | `Port_DOUT.Dout.Qf1OpenPulse` | X2_3、X2_4 | 经外部K2驱动QF1分闸 | 脉冲 |
| bit2 | `Port_DOUT.Dout.Kt1Hold` | X2_5、X2_6 | 经外部K3使KT1吸合，旁路预充电阻 | 电平保持 |
| bit3 | `Port_DOUT.Dout.AcRunning` | X2_7、X2_8 | AC运行指示 | 闭环RUNNING为1 |
| bit4 | `Port_DOUT.Dout.AcFault` | X3_1、X3_2 | AC故障指示 | 闭环FAULT为1 |
| bit5~7 | `Reserved` | X3_3~X3_8 | 备用 | 本程序不控制 |

QF1合、分线圈互斥，默认脉宽`g_chb_dab_params.qf1_pulse_10ms=50`，即500ms。脉冲到期只清bit0/1，KT1的bit2不清。重复同方向命令不会延长正在输出的脉冲。

KT1吸合后保持1，停机或故障释放为0。它是预充电阻的旁路接触器，不是与QF1并联的第三个进线开关。

重复发送KT1同一合/分保持命令时，输出保持原值，不重新开始反馈等待计时，也不清零反馈确认计数。只有目标或保持输出实际改变，才重新建立本次动作的反馈等待窗口。

实际输出路径：

`Chb_SetQf1()`或`Chb_SetKt1()` → `Port_DOUT.Dout` → `Port_IO_Out()` → `FPGA_Interface[IO_PluginUnit_2 - 2].DOUT.SwitchINOUT16` → 301 FPGA → 板载继电器 → 外部K1/K2/K3 → QF1/KT1。

`IO_PluginUnit_2`当前宏值为3，数组下标为1。TI编译器确认`sizeof(FPGA_InterfaceBLOCK)=0x200`，所以实际DSP字节地址为：

| 地址 | 权限 | 用途 |
|---|---|---|
| `0x60000240` | R/W | S301 DOUT，bit0~4见上表 |
| `0x600003C0` | R | S301实时DIN |
| `0x600003C2` | R | S301故障锁存DIN |

这些是DSP的EMIFA字节地址，不能当作屏幕Modbus地址。

## 3. 实际开入

| DSP DIN位 | `XXG_SwitchINOUT.Din`成员 | S301端子 | 图纸信号 |
|---|---|---|---|
| bit0 | `EmergencyStop` | X1_2 | 紧急停机SB1 |
| bit1 | `FaultReset` | X1_3 | 信号复归SB2 |
| bit2 | `RemoteControl` | X1_4 | 远方控制SA1 |
| bit3 | `Start` | X1_5 | 开机SB3 |
| bit4 | `Stop` | X1_6 | 停机SB4 |
| bit5 | `Kt1Closed` | X1_7 | KT1合位辅助触点 |
| bit6 | `Qf1Closed` | X1_8 | QF1合位辅助触点 |
| bit7 | `Qf1Open` | X1_9 | QF1分位辅助触点 |

X1_1为COM，X1_10为+24V。寄存器1表示相应触点闭合；QF1合位和分位必须各自读取。两位同为0表示动作中或反馈缺失，两位同为1表示反馈矛盾，均不能认为到位。

`Port_DINRead()`现在只读原始字，不再夹带旧隔离、接地、外部断路器状态解析。DI1~DI5已按图纸命名并可由原始DIN观察；本次没有新增面板按钮启动/停机/复归命令服务，不把DI3直接当作屏幕的自动/手动方式。DI6~DI8接入本次实际开关反馈联锁。

## 4. 启动、停机及故障流程

当前`ChbBuildConfig.h`默认：

```c
#define SST_ENABLE_SWITCH_OUTPUT   1U
#define SST_ENABLE_SWITCH_FEEDBACK 1U
```

完整实柜闭环用上述配置。不接开关板的单板波形调试可同时改为0；不能保持反馈为1而关闭输出。单相、三相共用相同开关流程，不受`SST_PHASE_A_ONLY_TEST`限制。控制模式仍由`g_chb_dab_command.ac_mode`选择；本次未改变原来的默认开环模式和PI/保护参数。

闭环启动步骤：

1. STOPPED确认QF1实际分位：`qf1_open=1`、`qf1_closed=0`，且`kt1_closed=0`，连续3个10ms节拍一致。
2. 收到CHB运行请求，进入PRECHARGE：释放KT1，发QF1合闸脉冲。此时不发PWM。
3. 等待QF1合位：`qf1_closed=1`、`qf1_open=0`，KT1仍未合，连续3拍后才允许累计预充电压达标时间。电压已达标但QF1未到位也不会跳过。
4. 模块电压达到`precharge_voltage_v`并连续满足`precharge_stable_10ms`后，进入`CHB_STATE_KT1_SETTLE`（数值仍为2），保持KT1输出1。
5. 等待KT1真实合位，且QF1仍在合位，连续确认3拍，并等待`kt1_settle_10ms`机械稳定时间后进入WAIT_PLL。KT1不合到位时不会进入该步骤。
6. PLL和母线条件满足后进入RUNNING，CHB发波；DAB仍由其独立命令决定，未新增与CHB启动绑定。

开关动作反馈最多等1s，运行中反馈连续不一致30ms进入`CHB_FAULT_SWITCH_FEEDBACK=7`。动作超时以本次开关动作开始计时，不以整个STOPPED已停留的时长计时；反馈抖动不会无限延长本次动作期限。

预充电压与PLL锁定均要求连续确认。启动中途若QF1/KT1反馈不到位，立即清零这两个连续确认计数；实际触点重新连续稳定3拍后，再从零累计电压或PLL确认，不能接续反馈丢失前的计数。

停机/故障沿用先封波、再释放KT1、再发QF1分闸脉冲。故障复位须确认QF1分位和KT1释放连续稳定。开环单板模式不自动合分QF1/KT1，也不以开关反馈阻挡单板发波；反馈宏开启时仍每10ms读一次供观察。

## 5. 屏幕命令及反馈

下列均为十六进制Modbus逻辑字地址，原地址不变。控制仍需写完16字块1后最后写`0x1FFE=1`。

| 地址 | 权限 | 定义 |
|---|---|---|
| `0x00F6` | W请求 | bit0吸合KT1，bit1合QF1；bit2/3忽略 |
| `0x00F7` | W请求 | bit0释放KT1，bit1分QF1并释放KT1；同包分闸优先 |
| `0x00FB` | W请求 | bit0允许合闸，bit1禁止合闸；同时为1拒绝 |
| `0x0501` | R | bit0实际KT1合位、bit1实际QF1合位、bit2实际QF1分位；其他PWM及方式位保持 |
| `0x1990` | R | bit0 QF1合闸目标、bit1 KT1保持命令，不能当作触点反馈 |
| `0x1991` | R | 实时S301 DIN原始字，bit0~7见开入表 |
| `0x1992` | R | bit0实际QF1合位、bit1实际KT1合位、bit2实际QF1分位 |
| `0x1985` | R | 最近块1处理结果；0受理、4忙、5拒绝 |
| `0x1989` | R | 控制状态：0停机、1预充、2 KT1稳定等待、3等待PLL、4运行、5故障 |
| `0x198A` | R | 核心故障码；7为开关反馈异常 |

屏幕的遥控位顺序是KT1/QF1；DO硬件位顺序是QF1合/QF1分/KT1。两者用途不同，解析注释和输出函数中分别明确，不能直接把屏幕开关字写到DOUT。

手动操作须PWM和运行命令均已停止，且`PortRunFLAG.Bbits.Port_AutoOrManual=0`；合闸还需许可及无故障。该方式来自遥调块`0x01FF`的bit1（1自动、0手动），并非DI3。保持原块其他参数不变，完整43字后最后写`0x1FFE=2`。

手动合闸分两笔：先`00F6 bit1=1`合QF1，看到DI7=1/DI8=0后，再`00F6 bit0=1`保持KT1。分QF1时即使同包还有KT1合命令，也先释放KT1并只执行QF1分闸。重复合/分命令不延长正在输出的QF1脉冲；上次分闸脉冲已结束但实际仍未分到位时，可以再次按分闸重试。

## 6. 调试与验收

先在无功率的开关动作试验中观察以下变量，再进行完整预充：

```text
Port_DOUT.Dout
g_chb_dab_status.switch_din_raw
g_chb_dab_status.qf1_close_command
g_chb_dab_status.kt1_close_command
g_chb_dab_status.qf1_closed
g_chb_dab_status.qf1_open
g_chb_dab_status.kt1_closed
g_chb_dab_status.switch_stable_count
g_chb_dab_status.switch_mismatch_count
g_chb_dab_status.state
g_chb_dab_status.fault_code
```

1. QF1分、KT1释放时，若其他按钮都未动作，DIN应为`0x0080`；QF1合而KT1释放应为`0x0040`；QF1、KT1均合应为`0x0060`。其他输入触点动作时，相应低5位可能为1。
2. 单独合QF1，确认DO1吸合后约500ms释放、DO2不同时吸合；分QF1反向检查。以实际线圈规格核定`qf1_pulse_10ms`，图纸没有给出线圈允许脉宽。
3. 合KT1后观察DO3持续保持，等待超过QF1脉宽仍应吸合；释放KT1后DO3为0。
4. 故意不提供QF1合位反馈，即使预充电压已达标，也应停在预充步骤，最终故障7；KT1合位缺失也应阻止进入PLL/发波。
5. 完整闭环启动观察STOPPED→PRECHARGE→KT1_SETTLE→WAIT_PLL→RUNNING及实际触点；再撤销运行，确认先封波、KT1释放、QF1分闸。

输出脉冲清除和反馈读取都在后台10ms服务完成；不要在合/分闸输出期间暂停DSP，因为断点会暂停脉宽计时。记录变量可用CCS持续刷新或现有通信；需要停点分析时先断开线圈供电。

## 9. 继续复查与补充修正

补充复查通过实际执行旧源码的测试，确认并修正了以下两处问题：

1. `ChbDabControl_Service()`在反馈未稳定时直接返回，原先保留了预充电压和PLL锁定的累计确认次数。现在在返回前清零`s_precharge_stable_count`和`s_pll_lock_10ms_count`，反馈恢复后须重新连续确认，避免把反馈中断前后的时间拼接起来。
2. `Chb_SetKt1()`原先每次收到保持指令均重新计时。现在目标位置和保持输出均未改变时，只同步输出后返回，不修改动作开始节拍和反馈计数。屏幕重复发送合KT1或释放KT1不能推迟原本1s的动作反馈超时。

新增4个回归场景：预充阶段中断反馈、PLL等待阶段中断反馈、反复合KT1而反馈不到位、反复释放KT1而反馈不到位。修改前这4项均失败，修改后在单相和三相反馈开启配置下均通过；输出关闭、反馈关闭组合也正常。

补充验证结果：`switch_io.py`全部6种配置通过；`dpram_switch_maintenance.py`的6种有效配置通过，2种无输出但启用反馈的非法配置按预期拒绝编译；`dpram_screen.py`和`dpram_commands.py`各4种配置通过。未改变第8节记录的既有全量控制测试限制。

旧源码失败复现保存在`build/switch_301_continuation_20261118/reproduction.txt`，修复后测试输出见同目录`switch_io_after.txt`、`dpram_switch_maintenance_after.txt`、`dpram_screen.log`、`dpram_commands.log`。这两处修正均未增加10kHz正常采样中断的开关读取或等待。
